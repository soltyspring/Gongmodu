# 증권사 청약 비교와 가정 계산

2026-10-25 사용자가 첨부한 공모주린이 방송 표를 필요한 정보의 기준으로 삼았어요. 방송 화면·스프레드시트를 데이터 원본으로 재사용하지 않아요. 공개 자료에서 해당 유튜버의 수집 코드·제휴 데이터 원천은 확인하지 못했어요. 아래 구현은 증권사 공식 화면과 그 화면이 사용하는 공개 조회 요청을 직접 확인한 결과예요.

iM 공식 안내는 약 5분 지연이라고 설명해요. 원본 JSON은 시각을 제공하지 않으므로 앱 수집 시각을 원본 갱신 시각으로 표시하지 않아요. 삼성 날짜 조회는 원본 기준일만 확인 가능하고 시각은 미제공으로 표시해요. 통합 경쟁률을 증권사별 일반/비례 경쟁률 대신 쓰지 않아요.

iM 화면의 일반청약 표시 모드(`p_a68=N`)만 해석해요. 다른 모드의 전체 투자자 배정물량을 개인 일반청약 배정물량으로 사용하지 않아요. 대신증권은 총·비례 경쟁률과 청약건수를 제공하지만 원본 집계 시각과 신청주수는 해당 월별 표에서 확인되지 않아요. 페이지의 ‘처리결과’ 시각은 요청 처리 시각이므로 원본 집계 시각으로 쓰지 않아요. 원본 신청주수가 없으면 반올림된 경쟁률로 역산해 채우지 않아요.

현재 수집 범위의 2026-10-25 실제 확인: iM 아이엠1호 공모는 청약 시작 전이고 공시·증권사 안내에 공모가 2,000원, 배정 1,250,000주, 한도 125,000주, 환불 10/29, 상장 예정 11/4가 있었어요. 청약 전의 0 경쟁률·0 건수는 앱에서 ‘청약 전’과 미집계로 표시해요. 삼성 크리에이츠의 종료 청약 집계도 읽었으나 시간 기준을 확인할 수 없어 최종 확정 배정 결과라고 표시하지 않아요.

추가로 대신증권 공식 표와 앱 API에서 이에스티의 종료 청약 집계(총 경쟁률 28.95:1, 비례 57.9:1, 건수 50,437)를 같은 회사·기간으로 연결했어요. 이 값 역시 해당 조회 시점의 증권사 집계이며 확정 배정 결과라는 의미는 아니에요.

## 갱신과 장애

서버 `/api/competition`은 증권사·조회일별 5분 캐시와 동시 요청 공유를 사용해요. 실패 후 1분 안에는 재요청하지 않아요. 마지막 정상값이 있으면 원래 수집 시각과 `stale`을 유지해요. 첫 수집 실패·지원하지 않는 증권사·종목/기간 매칭 실패는 각각 빈 값과 상태로 제공하며 0으로 만들지 않아요. 청약 시작 하루 전부터, 종료 후 14일 이내만 외부 조회를 수행해요. 브라우저는 화면이 보일 때 5분 간격으로 갱신해요. DART 일정의 1시간 캐시와 별도예요.

증권사 날짜는 공모 회차가 일치하고 stale이 아니며, 증권사끼리 날짜가 충돌하지 않을 때만 달력에 보완해요. 기존 DART 이벤트가 우선이에요. ‘증권사 안내’ 링크와 `broker-announcement` 근거를 저장하며 캘린더 내보내기에도 그 URL을 사용해요. 추정 상장일이나 납입일을 기계적으로 환불일로 바꾸는 방식은 사용하지 않아요.

## 계산 기준

- 필요 증거금 = 공모가 가정 × 청약주수 × 증거금률 가정
- 비례 이론배정 = 청약주수 ÷ 최종 비례 경쟁률 가정
- 단리 이자 = 필요 증거금 × 연 이자율 가정 ÷ 100 × 사용일수 ÷ 365
- 이자 + 수수료 = 단리 이자 + 수수료 가정
- 가정 균등 참고수량 = 확인된 최소 균등배정 예정물량 ÷ 최종 청약건수 가정
- 가정 총 증거금 = 최종 신청주수 가정 × 공모가 가정 × 증거금률 가정
- 가정 일반 경쟁률 = 최종 신청주수 가정 ÷ 확인된 일반 배정물량

공시 청약 단위·한도를 확인한 경우 어긋난 주수는 계산하지 않아요. 연 이자율 초기값 2.85%와 수수료 초기값 0원은 사용자 수정용 가정이며 현재 대출상품의 금리·수수료 안내가 아니에요. 사용기간은 청약 마감일부터 환불일까지를 초기값으로 사용하지만 실제 입금일에 맞게 바꿀 수 있어요. 최소 필요증거금의 모집가액이 미확정이면 그 사실을 표시해요.
