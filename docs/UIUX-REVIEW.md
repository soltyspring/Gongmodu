# 공모두 UI/UX 점검 · 2026-10-26

## 공식 문서와 적용

- [앱인토스 디자인 도구](https://developers-apps-in-toss.toss.im/design/prepare/design): 375px 기준, Top/ListRow 중심의 구성 권장. 기존 TDS Provider와 버튼을 유지하고 상세 청약 정보에 실제 TDS ListRow를 적용했습니다.
- [UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide): 독립된 브랜드, 2~5개 플로팅 탭, 예측 가능한 CTA와 해요체. 공모두의 녹색 브랜드와 3개 플로팅 탭을 유지합니다. 첫 진입을 막는 광고·알림 동의나 이탈 방해는 없습니다.
- [TDS](https://developers-apps-in-toss.toss.im/design/components): 앱인토스 서비스 안에서 사용하는 기존 패키지를 활용합니다. 외부 서비스용 UI Kit을 재배포하지 않습니다.
- [공식 문서가 연결하는 접근성 자료](https://frontend-fundamentals.com/a11y/): 버튼의 이름, 키보드 포커스, 대화상자 닫기·복귀, 색상 외 일정 종류 설명을 점검했습니다.

## 바꾼 흐름

홈은 가장 가까운 청약을 먼저 보여주고 달력과 다가오는 일정이 이어집니다. 큰 소개 문구와 내보내기는 다시 추가하지 않았습니다. 목록의 날짜를 별도 줄로 보여줘 증권사 이름 때문에 날짜가 말줄임되지 않게 했습니다.

상세는 회사·청약 날짜, 청약/환불/상장 요약, 청약 정보, 필요할 때 펼치는 공시 근거 순서입니다. 관심 저장은 TDS의 큰 버튼으로, 공시 원문은 외부 페이지임을 알리는 링크로 제공합니다. 상장일 미확인은 확인 전으로 표시하며 날짜를 만들어내지 않습니다.

관심 아이콘의 터치 영역은 44px, 목록 보조 글씨는 모바일 13px로 조정했습니다. 네이티브 상단바가 있는 토스에서는 중복 웹 헤더를 숨기는 기존 동작을 유지합니다.

상세 주소로 직접 들어온 경우 수집 데이터 응답을 기다리는 동안 로딩을 표시합니다. 응답 전 잠깐 나타나던 ‘일정을 찾을 수 없어요’ 문구를 없애고 지연 응답 브라우저 검사로 확인했습니다.

## 데이터 경험

우분투에서 6시간마다 수집하고 앱은 마지막 정상 결과만 조회합니다. DART 재연결 배너와 5초 반복 확인을 제거했습니다. 상단 확인 시각에는 날짜도 포함해 전날 데이터를 오늘 데이터로 오해하지 않게 했습니다. API가 실제로 연결되지 않고 화면에 데이터가 하나도 없을 때는 재시도 안내를 제공합니다.

## 시각 점검

기존 Pastel consumer 방향(seed 2140653618), 녹색 브랜드와 Pretendard를 유지했습니다. 새로운 방향 추첨이나 이미지 자산 추가는 없습니다. 실제 공개 API를 연결해 375·390·768·1440px에서 검사했습니다. 측정상 FAIL 0, WARN 2입니다. 작은 글씨 경고는 주로 달력의 보조 라벨이며 전체 종목명은 날짜 선택 후 목록에서 확인합니다. 카드 높이 경고는 왼쪽 청약/일정 두 블록과 오른쪽 월간 달력의 높이 차이로, 서로 다른 정보 영역의 자연 높이를 유지했습니다.

최종 화면 평가(자체 점검): 정보 위계 4/5, 읽기 4/5, 조작 4/5, 일관성 4/5. 달력의 짧은 종목명은 작은 화면에서 여전히 잘릴 수 있어 선택한 날짜 목록으로 보완합니다. 이 점검은 토스 심사 통과나 실제 iOS/Android 양쪽의 검증을 대체하지 않습니다.
