# DART 증권신고서 기반 청약 일정

2026-10-25에 Google Calendar 수집을 제거하고 OpenDART로 전환했어요. 입력한 인증키로 실제 API 수집과 화면 연결을 확인했어요. 인증키는 서버의 `.env`에서만 읽고 브라우저 응답·공시 스냅샷·웹 번들에는 포함하지 않아요.

## 사용하는 공식 API

| 단계 | API | 용도 |
| --- | --- | --- |
| 1 | [공시 검색: list.json](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001) | C001 지분증권 신고서의 최종보고서 검색, 전 페이지 조회 |
| 2 | [지분증권 주요정보: estkRs.json](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS006&apiId=2020054) | 청약기일(sbd), 납입기일(pymd), 배정공고일(asand), 인수인(actnmn), 모집가액(slprc) |
| 3 | [공시 원본: document.xml](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019003) | ZIP 안의 XML/HTML 원문에서 상장공모 여부와 정정 신고서 확인 |

원본 URL은 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=접수번호`예요. 전체 참고 링크는 [DART 청약 달력](https://dart.fss.or.kr/dsac008/main.do)이에요.

## 정정 처리

`last_reprt_at=Y`로 최종보고서를 검색해요. 주요정보의 접수번호가 최종 신고서와 같을 때만 그 정보를 사용해요. 실 API에서 ‘발행조건확정’ 신고서와 주요정보의 접수번호가 다른 사례를 확인했어요. 이때 이전 요약을 새 공시에 붙이지 않고, **최종 신고서 원문의 요약 표를 직접 읽어요.** 정정 전·후 표가 함께 있는 경우 마지막 완전한 요약 표를 사용해요. 표를 일관되게 읽지 못하면 원문 확인 대상으로 제외해요.

회사 고유번호와 확인된 최초 제출일로 공모 회차 ID를 만들어요. 정정으로 청약 날짜·접수번호가 바뀌어도 관심 저장 ID와 내보내기 UID는 유지해요. 최초 제출일을 확인하지 못한 정정 공시는 다른 회차와 섞지 않고 제외해요. 기존 회사명만 일치한다고 서로 다른 공모를 연결하지 않아요.

철회 표시 또는 후속 정정 대기 표시가 있는 신고서는 진행 중인 청약으로 노출하지 않아요. 저장된 일정이 최신 결과에서 사라지면 기기 기록을 유지하되 원본 재확인을 안내해요. 앱이 철회 사유까지 판정하는 것은 아니에요.

## 표시 규칙

- 날짜는 한국 기준이에요. 청약 종료일을 포함해 보여주되 내부 모델과 ICS의 종료일은 다음 날로 저장해요.
- 원문에 명시된 전체 날짜만 파싱해요. 시작일/종료일이 불명확하거나 상충하면 추정하지 않아요.
- `pymd`는 **납입기일**로 표시해요. 값만 복사해 환불일로 바꾸지 않아요. 환불일·상장 예정일은 주요정보 API의 날짜 필드 대신 원문의 명시적 문장·표에서 확인해요. ‘초과 청약증거금은 주금납입기일 당일에 반환’이라고 명시된 경우에만 납입일과 연결하며 `payment-reference` 근거를 남겨요.
- `slprc`는 **모집(매출)가액**으로 표시해요. 희망 공모가·확정 공모가·최소 증거금으로 일괄 해석하지 않아요. 단위와 확정 여부는 원문에서 확인해야 해요.
- 원문의 상장공모 근거를 확인해요. 기존 상장사의 주주배정·제3자배정 등은 IPO로 노출하지 않아요.
- 이전 Google 캘린더 관심 기록은 삭제하지 않아요. ‘이전 출처’라고 구분하며 DART 검증 데이터로 다시 표시하지 않아요.
- 새 ICS 내보내기에는 공시 접수번호와 DART 원문 URL을 포함해요. 파일에는 정정이 자동 반영되지 않아요.

최종 ‘발행조건확정’ 공시의 ZIP은 변경 부분만 담은 사례가 있어요. 모집 절차 전문이 없으면 회사별 공시 이력을 `last_reprt_at=N`으로 조회해 최초 제출일이 같은 공모의 가장 최근 전문을 찾아요(최대 6개 후보). 이전 공시의 명시적 날짜는 청약기간이 현재와 같을 때만 보완하고, 최신 공시에 해당 날짜 변경·미정 문구가 있으면 보완하지 않아요. 환불을 납입기일과 연결하는 명시적 문구는 최신 납입기일을 사용해요. 근거 접수번호·URL·문장을 이전 원문 그대로 보존해 최신 신고서에서 읽은 것처럼 바꾸지 않아요.

모집 본문 구간의 표 위치를 기록해 정정 전 구간과 발행인 이력의 다른 회사 날짜를 제외해요. 날짜가 서로 충돌하거나 청약 마감 이전·120일 이후이면 추가하지 않아요. 상장 예정일은 확정 상장일을 의미하지 않아요. 브라우저에서 보완하는 증권사 안내 날짜는 `broker-announcement` 출처로 별도 구분하며 [경쟁률·증권사 데이터 규칙](COMPETITION-DATA.md)을 따라요.

2026-10-25 추가 검증에서는 DART 청약 28건에 환불 이벤트 25건을 추가했어요. 이 수집 범위에서 DART 원문으로 확인된 상장 예정일은 없었고, iM증권 공식 안내에서 아이엠1호의 상장 예정일 2026-11-04를 별도로 확인했어요. 이 날짜는 DART 근거로 표시하지 않아요.

## 수집·운영

주관사 정보는 접수번호와 회사 고유번호가 일치하는 API 인수인명을 우선 사용해요. 이 값이 비어 있으면 같은 접수번호 원문의 인수인 표에서 보완해요. `대표`/`공동` 표기, `대표주관회사`/`공동주관회사` 표기, 구분·명칭이 나뉜 다단 표를 인식해요. 인수수량 또는 인수금액과 인수인 헤더가 있는 표로 범위를 제한하고, 정정 전후 표는 마지막 확인 가능한 표를 사용해요. 종목 이름에 증권사명이 들어 있다는 이유로 추정하지 않아요.

각 일정의 `disclosure.brokerSource`는 `summary`(API 주요정보), `document`(동일 공시 원문 표), `unconfirmed`(미확인)를 기록해요. 수집 결과의 `quality`는 주관사·모집가액 미확인 건수와 주관사 점검 목록(`brokerReview`: 일정 ID·회사명·접수번호·원문 URL)을 제공해요. `npm run sync:dart` 출력과 `/api/status`에서도 확인할 수 있어요. 미확인 주관사가 있으면 화면에 건수를 표시하고 상세 원문 확인으로 연결해요. 이 목록은 점검 대상으로, 자동으로 사람이 검수하거나 푸시 알림을 보내는 기능은 아니에요. 공시 인수인이라고 해서 일반투자자 청약을 모두 받는 것은 아니므로 증권사 공지도 확인해야 해요.

2026-10-25 주관사 누락 보완 검증: SK증권제14호·한화플러스제6호·아이엠1호의 원문에 있던 `대표` 표기를 지원해 기존 누락 3건을 해결했어요. 향후 모든 공시 서식을 지원한다는 의미는 아니며 수집할 때마다 품질 건수를 다시 계산해요.

`.env`에 `DART_API_KEY`를 설정하고 `npm run sync:dart`로 최초 수집할 수 있어요. `npm run dev`의 API도 최초 조회 시 수집을 시작해요. 초기 수집 중에는 HTTP 503 `DART_SYNCING`을 반환하며 화면이 5초 뒤 다시 확인해요. 인증키가 없거나 잘못됐을 때 Google 피드나 예시 데이터로 대체하지 않아요.

정상 결과는 `.cache/dart-schedule.json`에 원자적으로 저장해요. API 재시작 후에도 마지막 결과를 읽어요. 1시간 이내에는 같은 결과를 사용하고, 만료 후 조회 시 백그라운드 수집을 시작해요. 새 수집이 실패하면 마지막 정상 결과와 원래 확인 시각을 유지하며 `stale: true`를 표시해요. 공시가 일부 불명확한 경우 포함하지 못한 공시가 있음을 화면에서 안내해요.

`GET /api/status`는 설정 여부·수집 여부·진행 건수·마지막 수집 시각·오류 코드만 반환해요. 인증키와 인증키가 들어간 요청 URL은 반환하지 않아요. OpenDART의 013(조회 없음)을 인증 오류·한도 초과·점검과 구분해요. 회사 간 요청에 기본 200ms 간격을 두고, 동시 사용자 요청은 하나의 수집으로 합쳐요.

## 범위와 한계

기본 조회 범위는 최근 180일 접수 공시예요. `DART_LOOKBACK_DAYS`로 1~365일 범위에서 바꿀 수 있어요. 전체 회사 공시 검색은 3개월 제한에 맞춰 89일씩 나눠요. API 주요정보의 기간 기준은 **최초 접수일**이므로 오래전에 제출한 공시의 최근 정정은 요약에서 빠질 수 있어요. 이때 최종 원문 표로 확인하거나, 해석이 불가능하면 제외해요.

현재 후보는 법인 구분 E(기타), N(코넥스)의 지분증권 신고서예요. 이미 유가증권/코스닥 회사로 분류된 과거 IPO의 완전한 이력 서비스가 아니에요. 이전 달 달력이 모든 과거 IPO를 포함한다고 해석하면 안 돼요. 또한 공시의 ‘청약기일’이 일반투자자 청약 대상인지, 증권사별 접수 시간이 무엇인지까지 자동 보증하지 않아요. 원문과 증권사 안내로 최종 확인해야 해요.

2026-10-25 첫 전환 검증에서는 31개 후보 공시 중 청약 일정 28개(다가오는 일정 21개)를 읽었어요. 3개는 요약 표·최초 제출일·국내 상장공모 여부를 확인하지 못해 제외했어요. 이 수치는 당시 수집 결과이며 고정된 서비스 수치가 아니에요. DART 출처 사용이 앱인토스 입점 승인을 보장하지는 않아요.
