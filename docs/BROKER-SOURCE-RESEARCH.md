KB는 경쟁률 표와 통합 경쟁률이 실시간 자료가 아니라고 안내하므로 원본 기준 시각을 보존해야 해요. 미래에셋 공식 FAQ는 경쟁률과 총청약건수를 온라인에서 확인할 수 있다고 설명하지만, 해당 안내만으로 공개 수집 API나 재제공 권한을 확인한 것은 아니에요.

NH의 공식 N2 PLUG 신청은 NH 계좌·서비스 신청·APPKEY/AppSecret 발급·Access Token 순서예요. 현재 확인된 API 목록에 원하는 항목이 없으므로 키 발급만 요청해 문제를 해결했다고 보지 않아요. 공식 문의 채널에 공모주 일반청약 경쟁률·청약건수·신청주수·배정물량·원본 시각 제공 여부를 확인하는 것이 선행 작업이에요. 이 조사에서 문의를 발송하지 않았어요.

## 서버 수집 방법

1. 공식 웹 조회 화면에서 개발자 도구 Network의 Fetch/XHR와 문서 요청을 확인하고, 종목 선택·조회 동작의 URL·메서드·공개 조회 파라미터를 기록해요.
2. 비로그인 환경에서 같은 공개 조회를 재현해 JSON인지 HTML 표인지, 페이지가 이어지는지, 값과 기준 시각이 어떤 필드인지 검증해요. 세션·인증이 필요한 경우 개인 계정 자동 로그인 대신 정식 API·허용된 제휴 피드를 검토해요.
3. `server/competition.ts`의 증권사 어댑터를 확장해 회사명과 청약 시작·종료일을 함께 매칭해요. 일반청약과 기관·ELS·실권주, 당사 경쟁률과 통합 경쟁률을 분리해요.
4. 앱에는 일반/비례 경쟁률, 청약건수, 신청주수, 배정물량, 원본 기준 시각, 앱 수집 시각, 지연·stale 상태를 공통 형식으로 반환해요. 필드가 없으면 null을 유지하고 반올림된 경쟁률로 신청주수를 역산해 채우지 않아요.
5. 현재와 같은 5분 캐시·동시 요청 공유·실패 시 과거 확인 시각 보존을 적용해요. 제공처의 갱신 주기나 호출 조건이 다르면 그 조건에 맞춰요. 공개 화면 데이터의 앱 재제공 범위도 출시 전에 확인해요.

현재 확인된 근거로는 KB의 경쟁률 팝업과 미래에셋 웹 조회 요청을 먼저 조사하는 것이 효율적이라는 판단이에요. 한국투자는 장중 상세 데이터 검증이 필요하고, NH는 원하는 API 항목의 지원 여부부터 확인해야 해요. 확인되지 않은 조회 URL·TR 코드를 만들어 사용하지 않아요.
